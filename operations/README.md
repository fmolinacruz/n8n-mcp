# Operations Directory

This directory contains scripts, documentation, and tools for managing the Git branching strategy and operational procedures for the n8n-mcp project.

## Directory Structure

```
operations/
├── docs/                    # Documentation
│   ├── GIT_STRATEGY_EVALUATION.md       # Main strategy document
│   ├── HISTORICAL_DATA_REPORT.md        # Audit trail template
│   ├── BRANCHING_STRATEGY.md            # User guide
│   ├── BRANCH_PROTECTION_RULES.md       # GitHub protection config
│   └── TEAM_COMMUNICATION_TEMPLATE.md   # Team notification template
│
└── scripts/                 # Automation scripts
    ├── setup-git-strategy.ps1           # Branch setup script (PowerShell)
    └── pre-commit-secret-check.sh       # Secret detection hook (Bash)
```

## Quick Start

### For Team Leads

1. **Review the strategy document:**
   ```bash
   cat operations/docs/GIT_STRATEGY_EVALUATION.md
   ```

2. **Set up branch protection on GitHub:**
   - Navigate to repository settings
   - Follow instructions in `BRANCH_PROTECTION_RULES.md`

3. **Create client branches:**
   ```powershell
   # Dry run first
   ./operations/scripts/setup-git-strategy.ps1 -DryRun
   
   # Then create branches
   ./operations/scripts/setup-git-strategy.ps1
   ```

4. **Communicate to team:**
   - Review `TEAM_COMMUNICATION_TEMPLATE.md`
   - Customize and send to team

### For Developers

1. **Install pre-commit hook:**
   ```bash
   ./operations/scripts/pre-commit-secret-check.sh --install
   ```

2. **Read the branching guide:**
   ```bash
   cat operations/docs/BRANCHING_STRATEGY.md
   ```

3. **Follow branch naming conventions:**
   - Core features: `feature/{scope}/{description}`
   - Bug fixes: `fix/{scope}/{description}`
   - Client work: `client/{client-name}/{description}`

### For Security Team

1. **Review security considerations:**
   ```bash
   cat operations/docs/GIT_STRATEGY_EVALUATION.md
   ```

2. **Run secret audit (during Phase 2):**
   ```bash
   git log --all -p -S "API_KEY" > operations/docs/secret_audit.txt
   ```

3. **Complete audit trail:**
   - Fill in `HISTORICAL_DATA_REPORT.md`
   - Document findings and actions taken

## Scripts

### setup-git-strategy.ps1
**Language:** PowerShell  
**Purpose:** Automate branch creation and documentation generation  
**Usage:**
```powershell
# Show help
./operations/scripts/setup-git-strategy.ps1 -Help

# Dry run (no changes)
./operations/scripts/setup-git-strategy.ps1 -DryRun

# Create branches
./operations/scripts/setup-git-strategy.ps1

# Skip branch creation, only generate docs
./operations/scripts/setup-git-strategy.ps1 -SkipBranchCreation
```

**What it does:**
- Creates client branches (WDL, Villakuyaya)
- Generates branch protection documentation
- Creates team communication template
- Provides next steps summary

### pre-commit-secret-check.sh
**Language:** Bash  
**Purpose:** Prevent secret commits via pre-commit hook  
**Usage:**
```bash
# Install hook
./operations/scripts/pre-commit-secret-check.sh --install

# Uninstall hook
./operations/scripts/pre-commit-secret-check.sh --uninstall

# Manual run
./operations/scripts/pre-commit-secret-check.sh

# Show help
./operations/scripts/pre-commit-secret-check.sh --help
```

**What it detects:**
- API keys and tokens
- Passwords
- AWS credentials
- Private keys
- Hardcoded secrets

## Implementation Phases

### Phase 0: Immediate (1-2 days) 🚨
**Status:** Ready for execution  
**Actions:**
1. Lock down main branch on GitHub
2. Communicate new policy to team
3. Stakeholder review and approval

### Phase 1: Week 1
**Status:** Scripts and docs ready  
**Actions:**
1. Run `setup-git-strategy.ps1`
2. Configure GitHub teams
3. Install pre-commit hooks
4. Run secret audit

### Phase 2: Weeks 2-3 (possibly 4) ⚠️
**Status:** Manual process required  
**Actions:**
1. Identify client commits
2. Cherry-pick to client branches
3. Document in HISTORICAL_DATA_REPORT.md
4. Thorough testing

### Phase 3: Week 4
**Status:** Automation and training  
**Actions:**
1. Verify GitHub Actions workflows
2. Update documentation
3. Conduct team training
4. Final validation

## GitHub Actions Workflows

### branch-validation.yml
**Purpose:** Validate branch naming and client code location  
**Triggers:** Push, Pull Request  
**Checks:**
- Branch naming convention compliance
- No client code on main branch
- Commit message quality

### secret-detection.yml
**Purpose:** Scan for secrets and credentials  
**Triggers:** Push, Pull Request  
**Checks:**
- Pattern-based secret detection
- URL credential scanning
- .env file detection
- TruffleHog scan (optional)

**Location:** `.github/workflows/`

## Troubleshooting

### PowerShell script won't run
**Problem:** Execution policy restriction  
**Solution:**
```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

### Pre-commit hook not working
**Problem:** Hook not executable or not installed  
**Solution:**
```bash
chmod +x operations/scripts/pre-commit-secret-check.sh
./operations/scripts/pre-commit-secret-check.sh --install
```

### Branch validation failing
**Problem:** Branch name doesn't follow convention  
**Solution:** Rename branch to match pattern
```bash
git branch -m old-name new-name
```

### Secret detection false positives
**Problem:** Example code flagged as secret  
**Solution:** Add markers like "example", "placeholder", or "fake"

## Security Best Practices

1. **Never bypass pre-commit hooks** without security team approval
2. **Always review secret scan results** before dismissing warnings
3. **Rotate credentials immediately** if exposed
4. **Document all security incidents** in HISTORICAL_DATA_REPORT.md
5. **Keep branch protection rules active** - don't disable for convenience
